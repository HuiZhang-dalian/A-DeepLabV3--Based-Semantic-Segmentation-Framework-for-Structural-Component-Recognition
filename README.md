# Reproducing S3DIS Area 5 Semantic Evaluation

This repository evaluates semantic labels on S3DIS Area 5 through a four-stage workflow:

1. Project each S3DIS point-cloud scene into 36 RGB views and save a point-index map for every view.
2. Run DeepLabV3+ on the projected images and save a pixel-level semantic-label CSV for each view.
3. Reproject the pixel labels to the original 3D points and fuse predictions from multiple views by majority voting.
4. Compare the fused point-label CSV with the S3DIS ground-truth label CSV using `eval.py` to calculate mIoU.

The commands below show the intended sequence. The current projection, prediction, and reprojection scripts use paths defined in each script's `main()` function rather than command-line arguments. Update those paths to match your local data before running. The evaluation script in this draft is provided as `eval.py` and expects the same two-column label format described below.

## Datasets

Download the datasets from their original providers and follow their access and use conditions. The datasets are not redistributed in this repository.

- ADE20K: https://groups.csail.mit.edu/vision/datasets/ADE20K/
- S3DIS: https://cvgl.stanford.edu/resources.html

ADE20K is used to train the 2D semantic segmentation model. The reported S3DIS evaluation is performed on Area 5; Area 5 labels must not be used for training, fine-tuning, or model selection.

The projection script currently reads point-cloud CSV files with a header row followed by columns `x, y, z, r, g, b`. It skips the first row and reads the first six columns. Prepare the S3DIS room/scene point clouds in this format, or adapt the loader if the downloaded S3DIS files use another format. Keep the ground-truth label CSV files separate for the final evaluation.

## CSV Format Required Before Evaluation

The ground-truth S3DIS label file used by `eval.py` must first be processed into the same CSV format as the output of `reproject_semantic_labels.py`. Each CSV must contain these columns:

```csv
point_id,label,source_views
1,1,"0,1,2"
2,4,"0,1"
```

`point_id` identifies the original point, and `label` is the integer semantic class ID. The example above is a raw prediction CSV: ADE20K label `1` represents wall and label `4` represents floor. For the same two points, the ground-truth CSV must contain S3DIS labels `9` and `7`, respectively. By default, `eval.py` converts raw ADE20K predictions to the six S3DIS target IDs and assigns every other prediction label to `0`. If the prediction CSV has already been converted, pass `--pred-label-space s3dis` to avoid converting it a second time. Point IDs must match those generated by the projection script: real point IDs start at `1`, while point-index value `0` denotes image background and must not be treated as a real point.

`source_views` is optional for evaluation and is ignored by `eval.py`; it records the view IDs that contributed to the fused prediction. Users must independently convert the S3DIS ground-truth point labels into this format before evaluation, preserving the original point IDs and assigning the corresponding S3DIS ground-truth label to `label`. Do not renumber the ground-truth labels to ADE20K IDs; apply the ADE20K-to-S3DIS mapping to predictions during evaluation.

The prediction and ground-truth CSVs must contain one row per point ID. Duplicate point IDs are rejected. Missing predictions and predictions converted to label `0` are reported and counted as false negatives for their valid ground-truth class, although they do not occupy a prediction column in the confusion matrix. Ground-truth labels outside the configured 13 class IDs, including `0`, are excluded. To evaluate all 13 classes, retain distinct nonzero ground-truth IDs for all 13 classes; do not collapse the other seven ground-truth classes to `0`.

## Model Checkpoint

The released weight file is `multi_view_semantic_labeling/deeplabv3plus.pth`. In `predict_semantic_labels.py`, replace the model initialization and weight-loading lines with:

```python
from pathlib import Path
import torch

device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
checkpoint_path = Path(__file__).resolve().with_name("deeplabv3plus.pth")
model = DeepLabV3Plus(
    num_classes=151, backbone="resnet50", pretrained_backbone=False
)
state_dict = torch.load(checkpoint_path, map_location="cpu", weights_only=True)
model.load_state_dict(state_dict, strict=True)
model.to(device)
model.eval()
```

In the current implementation, `backbone="resnet50"` constructs a ResNet-101 backbone; use this argument to match the existing model definition. Set the input image path and run `python multi_view_semantic_labeling/predict_semantic_labels.py` from the repository root.

## Run the Four Stages

### 1. Project point clouds into views

Edit `csv_paths` and `output_dir` in `multi_view_semantic_labeling/project_point_cloud_views.py`, then run:

```bash
python multi_view_semantic_labeling/project_point_cloud_views.py
```

The script generates 36 views (`view_00.png` through `view_35.png`) at 1920 × 1080 pixels. It also saves a matching point-index map for each view as `view_XX_index.csv`. These index maps are required by the reprojection step.

### 2. Predict semantic labels for projected images

Use the initialization argument and checkpoint-loading procedure in **Model Checkpoint** above, and set the image path in `multi_view_semantic_labeling/predict_semantic_labels.py`, then run:

```bash
python multi_view_semantic_labeling/predict_semantic_labels.py
```

The model preprocessing resizes images to 512 × 512 pixels and applies ImageNet channel normalization. For the full Area 5 evaluation, the prediction step must process all 36 views for every room and save each predicted pixel-label mask as a CSV named `segmentation_view_XX_pixel_labels.csv`. The current public script's `main()` demonstrates single-image inference and visualization; add or use the batch CSV-export routine that generated the prediction CSVs used in the reported evaluation.

### 3. Reproject and fuse view predictions

In `multi_view_semantic_labeling/reproject_semantic_labels.py`, set `label_folder`, `point_folder`, and `output_file` in the `__main__` block. The label and point-index files must use matching view IDs, for example `segmentation_view_00_pixel_labels.csv` and `view_00_index.csv`. Then run:

```bash
python multi_view_semantic_labeling/reproject_semantic_labels.py
```

The script maps pixel predictions to point IDs and uses majority voting to resolve points observed in multiple views. Ties are resolved by selecting the smallest label ID. The current reprojection script writes fused raw ADE20K labels. In the following evaluation step, `eval.py` converts these fused point labels to the six S3DIS target IDs and assigns all other predictions to `0`. Retain the `point_id` and `label` columns for evaluation.

### 4. Calculate mIoU

Prepare the S3DIS ground-truth labels in the same `point_id,label[,source_views]` format. During the conversion from 2D semantic labels to 3D point labels, only the following six semantic classes retain their corresponding S3DIS IDs; all other prediction classes are assigned label `0`. This conversion is built into `eval.py` and is applied to the fused raw ADE20K point predictions. No external prediction-mapping CSV is required.

The confirmed six-class mapping is:

| Semantic class | ADE20K prediction ID | Converted 3D prediction ID |
| --- | ---: | ---: |
| Wall | 1 | 9 |
| Floor | 4 | 7 |
| Ceiling | 6 | 3 |
| Window | 9 | 10 |
| Door | 15 | 6 |
| Column | 43 | 11 |
| All other prediction classes | All other IDs | 0 |

The built-in conversion is:

```python
ADE20K_TO_S3DIS = {1: 9, 4: 7, 6: 3, 9: 10, 15: 6, 43: 11}
converted_label = ADE20K_TO_S3DIS.get(raw_ade20k_label, 0)
```

These IDs specify the label encoding used in this project. For raw ADE20K inputs, do not subtract one or otherwise renumber labels before evaluation. For inputs already converted to the six S3DIS IDs and `0`, use `--pred-label-space s3dis`; this preserves the six target IDs and converts any other prediction ID to `0`.

The evaluator uses `--six-class-ids 9,7,3,10,6,11` by default, corresponding to wall, floor, ceiling, window, door, and column. Users may assign nonzero integer IDs to the remaining seven ground-truth classes. These IDs must be distinct from one another and must not conflict with `3,6,7,9,10,11`; `0` is reserved for other predictions. Use consistent class assignments in the ground-truth CSV, `--class-ids`, and `--class-names`. Use the following command template:

```bash
python eval.py \
  --pred-csv /path/to/fused_point_labels.csv \
  --gt-csv /path/to/area5_ground_truth_point_labels.csv \
  --pred-label-space ade20k \
  --class-ids "<six fixed IDs plus seven unique nonzero user-defined IDs, comma-separated>" \
  --class-names "<comma-separated 13 class names in the same order>" \
  --six-class-ids 9,7,3,10,6,11 \
  --output-dir /path/to/evaluation_results
```

Replace the angle-bracket placeholders before running, listing exactly 13 distinct nonzero ground-truth class IDs and their corresponding names in the same order. The other seven classes do not need ADE20K-to-S3DIS prediction mappings: predictions outside the six target classes become `0`. Keep all 13 ground-truth classes in the evaluation when calculating the six-class mean, because predicting a target class on another ground-truth class contributes a false positive. The converted predictions are saved as `converted_prediction_labels.csv` in the output directory.

## S3DIS Classes and Metrics

The six BIM-relevant classes use the confirmed S3DIS IDs `9` (wall), `7` (floor), `3` (ceiling), `10` (window), `6` (door), and `11` (column). Convert predictions with the ADE20K-to-S3DIS mapping above before comparing semantic labels. Keep the point-ID alignment separate from this class-ID conversion.

Accumulate results over the full valid 13-class ground-truth point set and report per-class IoUs, 13-class mIoU, and the mean IoU of the six target classes from the same evaluation. Prediction label `0` is not an additional evaluated class: on a valid ground-truth point it contributes a false negative for that point's class. With this six-target prediction scheme, the other seven classes cannot have true positives, so their IoUs are `0` when they have ground-truth points. A class with zero union is reported with an undefined IoU and excluded from the mean. Record the user-defined ground-truth IDs and class names with the evaluation configuration. A consistent renumbering of the remaining seven ground-truth classes does not change the metrics.
